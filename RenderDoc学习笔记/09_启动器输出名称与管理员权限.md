# 09：启动器的输出文件名与管理员权限

## 这次终于改到输出文件名了，但改的是启动器

第 08 节改的是启动器“去启动谁”；这里改的是“启动器自己叫什么”。两者合起来是：

```text
rendertestui.exe（本节生成的启动器）
    ↓ 第 08 节的启动路径
qrendertest.exe（真正的 Qt 界面程序）
```

**本节不会生成 `qrendertest.exe`。** 真正界面程序的输出名仍需在它自己的项目中配套，不能把两个 EXE 混为一谈。

## 哪个属性真正控制文件名？

**这里控制输出基本名称的是 `TargetName`。** 项目类型是 EXE，所以 `rendertestui` 对应 `rendertestui.exe`，值里不用加 `.exe`。

`ProjectName` 是项目名称，本文件还用它拼接中间文件目录；`RootNamespace` 不会自动重命名源码中的 C++ 命名空间。不能以为改了这两项，就等于改了最终 EXE 名称。`PrimaryOutput` 按原项目保留并同步，最终仍要检查实际生成的文件。

## 管理员权限是独立改动，不是改名的必需步骤

在现有 `<Link>` 中添加：

```xml
<UACExecutionLevel>RequireAdministrator</UACExecutionLevel>
```

它让生成的启动器在清单中声明需要管理员权限。通过系统外壳正常启动时，若需要提权，会走 UAC 确认或凭据流程；获得权限后，它用普通 `CreateProcessW` 启动的界面程序通常继承其权限。

**改文件名并不要求增加管理员权限，也不是所有启动方式都会自动弹出 UAC。** 本项是否需要，取决于实际功能的权限需求；如果只是改名，不应把它当成必选配套。

重新构建，确认输出的是 `rendertestui.exe`；再通过它启动同目录的 `qrendertest.exe`，确认启动链完整。如果设置了权限项，还应检查生成 EXE 的清单和实际权限，而不是只看项目文件里写了什么。
